# 精简论文：渐进式披露式 Agent Skills 对上下文效率的影响

作者：示例作者团队（示例数据）

## 摘要

现代 LLM Agent 需要覆盖越来越多的专业任务，传统做法是把所有指令塞进单一
系统提示词，导致 token 消耗膨胀、注意力被稀释、KV Cache 前缀频繁失效。
本文提出并评估一种「渐进式披露（Progressive Disclosure）」的 Agent Skills
机制：先向 Agent 注入各 Skill 的薄目录（仅 name + description），当任务确实
需要时再按需加载完整的 SKILL.md 与子文档。

## 1. 研究背景与问题

- 随着 Agent 支持的任务种类增长，单一系统提示词呈线性膨胀。
- 长提示词带来三重代价：token 成本、注意力稀释、缓存前缀失效。
- 核心问题：能否让 Agent 知道自己有哪些能力，同时不让无关能力长期占用上下文？

## 2. 方法概述

- 第一层（元数据）：启动时只注入每个 Skill 的 name + description。
- 第二层（核心流程）：任务触发时加载完整 SKILL.md 作为 tool result。
- 第三层（细则）：按需读取 reference.md、脚本源码等子文档。
- description 应写成路由条件，并给出反例，降低误触发。
- Skill 可以捆绑可执行脚本，把知识升级为实际能力。

## 3. 关键结果

- 常驻上下文从全量指令降到薄目录。
- 工具数量恒定、前缀稳定，有利于 KV Cache 复用。
- 在需要专业 Skill 的任务上，效果与全量注入基线接近。
- 明确的反例能提升路由准确率，减少不相关任务上的误触发。

## 4. 局限性与讨论

- 触发依赖模型判断，判断失误可能漏加载 Skill。
- 第三方 Skill 是新的提示注入面，加载前需要审查。

## 5. 结论

渐进式披露把一次性塞满变为按需加载，在保持任务能力的同时降低常驻上下文，
是构建可扩展 Agent 能力体系的实用范式。
